# 年终述职助手 Skill

一个帮助你从零散工作材料中整理事实、补齐证据，并完成年度述职文字版与 PPT 制作交接包的 Agent Skill。

它不会拿到几份周报后就直接拼出一篇“看起来很完整”的述职。它会先读材料、识别岗位职责，再像采访者一样追问缺失的背景、个人贡献、结果和数据来源。等你确认事实后，它才开始写作。

## 适合哪些场景

- 年终述职、年度总结、绩效自评或晋升汇报
- 从周报、月报、OKR、项目复盘、会议纪要中提炼年度成果
- 工作成果很多，但不知道如何区分重点和日常事项
- 数据不完整，需要继续寻找可验证证据
- 非数据岗位，希望把效率、质量、覆盖、风险控制或协作价值表达清楚
- 材料中包含失败、延期、投诉或未达目标事项，需要决定是否写、怎么诚实地写
- 需要把确认后的内容交给另一个 PPT Agent 制作演示文稿

## 它会做什么

### 1. 先读材料，再提问

你可以直接提供已有的工作计划、OKR、周报、月报、季度总结、项目复盘、会议纪要、任务记录、数据报表、反馈记录或历史 AI 对话。

Skill 会区分“计划做”“正在做”“已经完成”和“结果已验证”，不会把计划自动当作成果。材料不齐也可以开始，它会根据岗位职责继续主动追问。

### 2. 区分团队成果与个人贡献

每项重点成果都会补齐这条链路：

`背景或目标 -> 难点 -> 本人行动与判断 -> 结果 -> 影响 -> 证据`

如果团队成果和个人贡献边界不清，Skill 会要求你进一步确认，不会把团队数字直接写成个人业绩。

### 3. 根据岗位选择证据

对于电商、运营、销售、增长等数据结果型工作，会重点核对基线、目标、实际值、时间范围、统计口径和数据出处。

对于研究、设计、行政、法务、项目管理、专业支持等非数据型工作，会继续寻找可验证的效率、质量、覆盖或采用、风险控制、复杂度、协作影响和定性反馈，而不是为了“量化”而编数字。

### 4. 单独处理负面或敏感内容

遇到失败、延期、未达标、投诉、事故、冲突或负面评价时，Skill 不会擅自写入，也不会偷偷删除，而是逐项请你选择：

- 不写
- 如实写
- 建设性重述
- 压缩带过

“建设性重述”只调整表达结构，保留真实事实和责任边界，补充行动、改进与当前状态。它不会帮你掩盖事实、甩锅或虚构补救结果。若公司模板明确要求披露，Skill 会提醒你不能通过省略来规避。

### 5. 对数据做三道确认

所有准备进入正式述职或图表的数据，都要经过：

1. 来源与统计口径核对
2. 事实摘要阶段的用户确认
3. 文字版锁定前的最终确认

未完成确认的数据不会被当作锁定事实，也不会交给 PPT Agent 制图。

## 最终会得到什么

正式交付包含两个独立文件：

- `述职-确认版.md`：经过二次确认并锁定的述职内容源
- `述职-PPT-Agent交接包.md`：交给下游 PPT 或 Presentations Skill 的执行规格

口述稿不会成为第三份正式文件。根据使用场景，它会作为文字版附录，或拆成 PPT 交接包里的逐页讲者备注。实际长度会根据汇报时长、个人语速、翻页和停顿时间估算，并在试讲后调整。

本 Skill 不直接生成 `.pptx`、网页 PPT 或其他幻灯片文件。它负责把经过确认的事实、主线、逐页策划、图表原始数据、来源和讲者备注交给下游 PPT Agent。

## 工作流程

```text
提供材料或接受采访
        ↓
建立事实库并主动追问缺口
        ↓
确认事实摘要、数据和敏感内容处理方式
        ↓
生成年度述职文字版
        ↓
用户二次确认并锁定版本
        ↓
生成对应版本的 PPT Agent 交接包
```

文字版锁定后如果再次修改，旧的 PPT 交接包会自动失效。新文字版需要重新确认、重新锁定，再生成新的交接包，避免下游继续使用过期事实。

## 安装

把仓库克隆下来后，把内层的 `write-performance-review` 文件夹复制到你的 Codex skills 目录即可。安装完成后，`SKILL.md` 应直接位于 `write-performance-review/` 目录下。

### 1. 克隆仓库

```bash
git clone https://github.com/soling0410/write-performance-review.git
```

### 2. 复制 skill 文件夹到 Codex skills 目录

Git Bash（Windows / macOS / Linux）：

```bash
cp -r write-performance-review/write-performance-review ~/.codex/skills/
```

PowerShell（Windows）：

```powershell
Copy-Item -Recurse write-performance-review\write-performance-review $env:USERPROFILE\.codex\skills\
```

### 3. 重启或刷新 Codex

安装完成后，`SKILL.md` 的最终位置是：

```text
~/.codex/skills/write-performance-review/SKILL.md
```

### 其他支持 Agent Skills 的工具

将内层 `write-performance-review` 文件夹放入该工具文档指定的 Skills 目录。不同客户端的目录位置和刷新方式可能不同，请以对应工具的官方说明为准。

## 如何开始

可以直接调用：

```text
$write-performance-review
```

也可以用自然语言开始，例如：

```text
我需要准备 2026 年度述职，汇报对象是部门负责人，预计讲 10 分钟。
我手上有 OKR、周报、两个项目复盘和一份数据报表。请先读材料并采访我，
不要直接写成稿；数据和负面事项都要先让我确认。
```

如果没有整理好的材料，也可以说：

```text
我没有完整材料，请从岗位职责开始，一次问我 1 到 3 个问题，
帮我逐步回忆这一年的工作。
```

## 建议准备的材料

不需要一次性备齐，先提供手边已有内容即可。

- 公司述职模板、绩效标准或评价维度
- 岗位职责和年度目标
- OKR、工作计划、周报、月报、季度总结
- 项目方案、复盘、会议纪要、任务记录
- 业务报表、统计截图或数据导出
- 客户、同事、管理者的反馈记录
- 事故、延期、未达目标及改进记录
- 下一年度计划和希望获得的支持

上传材料前，请先删除或替换不应交给 AI 的商业秘密、账号密码、客户隐私、个人敏感信息和受限制数据。

## 使用原则

- 不编造项目、数据、反馈、因果关系或个人贡献
- AI 历史记忆只能作为待核验线索，不能直接当事实
- 信息不足时继续追问，或明确保留缺口，不用空话填满
- 用户决定不写的负面事项，不会进入文字版、交接包或讲者备注
- 下游 PPT Agent 只能调整视觉和版式，不能改变已锁定的事实、数字、归因和保密处理

## 快速模式与完整模式

时间紧时，可以要求使用快速模式：优先收集任务要求、3 项核心成果、个人贡献、结果证据和下一年计划。快速模式仍不会跳过敏感内容决定和数据最终确认。

材料较多或用于正式绩效、晋升场景时，建议使用完整模式，覆盖全年材料、隐性贡献、问题复盘和证据来源。
