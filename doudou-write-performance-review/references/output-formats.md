# 双文件交付与口述内容

正式交付固定为两个独立 Markdown 文件。口述稿不单独成为第三个正式文件。

## 目录

- 一、交付合同
- 二、述职-确认版.md
- 三、述职-PPT-Agent交接包.md
- 四、口述稿或讲者备注
- 五、版本失效规则

## 一、交付合同

1. `述职-确认版.md`：用户确认并锁定的内容源。
2. `述职-PPT-Agent交接包.md`：交给下游 PPT/Presentations Skill 的执行规格。

本 Skill 不直接制作 PPT 文件。第二个文件只能基于第一个文件的已锁定版本生成。

## 二、述职-确认版.md

### 待确认阶段

首次生成时在文件头记录：

```yaml
status: 待二次确认
version: v0.1
generated_at: YYYY-MM-DD
review_period: 用户确认的述职周期
data_verification_status: 待完成
sensitive_content_decisions: 待完成
fact_ids: F-001..F-nnn
ppt_handoff_status: 未生成
```

根据每轮修改递增草稿小版本，例如 `v0.2`、`v0.3`。此阶段不得生成状态为“有效”的 PPT Agent 交接包。

### 正文结构

优先遵循公司模板。没有模板时使用：

- 岗位与年度目标概览
- 核心成果及影响
- 岗位履职与日常贡献
- 协作、带教或机制建设
- 未达预期事项与复盘
- 能力成长
- 下一阶段目标和所需支持
- 可选附录：指定时长的口述稿或提词稿

所有关键事实在正文旁或文末事实索引中关联 `F-001` 等编号。面向最终读者的正文可以保持自然，不要求每句都显示编号，但文件必须保留可追溯映射。

### 二次确认

请用户明确检查并确认：

- 事实、数字、日期和项目状态；
- 每个数字的单位、时间范围、口径、来源和最终表述；
- 团队成果与个人贡献边界；
- 每项负面或敏感内容是否纳入及采用何种表达；
- 述职主线、重点取舍和因果表述；
- 公司模板、篇幅、语气和保密处理；
- 口述稿的位置、时长和形式。

用户提出任何修改时，保持“待二次确认”，更新草稿版本并重新检查受影响事实。

### 版本锁定

只有用户明确表示“确认”“定稿”“锁定”或“可以交给 PPT Agent”时，才将文件头更新为：

```yaml
status: 已锁定
version: v1.0
confirmed_at: YYYY-MM-DD
confirmation_scope: 正文及已包含的附录
data_verification_status: 三道确认完成
sensitive_content_decisions: 已完成
fact_ids: F-001..F-nnn
ppt_handoff_status: 待生成
```

首次锁定为 `v1.0`。锁定后任何文字修改都必须进入新的待确认版本；重新确认后递增主版本，例如 `v2.0`。

## 三、述职-PPT-Agent交接包.md

生成前必须同时满足：

- 文字版状态为“已锁定”；
- 文字版有版本号和确认日期；
- 所有供 PPT 使用的事实都有锁定编号和来源；
- 所有供 PPT 使用的数字均已完成三道确认；
- 负面或敏感事项均已由用户决定，选择不写的内容已完全排除；
- 用户已确认汇报时长、受众和必要的视觉限制，或明确接受当前假设。

按 `references/ppt-agent-handoff.md` 生成。交接包文件头的 `source_version` 和 `source_confirmed_at` 必须与文字版完全一致。

## 四、口述稿或讲者备注

口述内容按用户场景选择放置位置：

- 独立提交或单独练习：放入 `述职-确认版.md` 附录。
- 配合 PPT 汇报：拆入 `述职-PPT-Agent交接包.md` 的逐页讲者备注。

先询问准确时长、语言、个人语速、互动与停顿需求，以及逐字稿或提词稿。

`目标内容长度 = 可用讲述分钟数 x 预计语速`

- 有试讲数据时，以用户自己的语速为准。
- 无试讲数据时，明确说明只是估算；中文可先按约 200 字/分钟、英文约 130 词/分钟规划。
- 从总时长预留约 10%-15% 给翻页、停顿、强调和现场波动。
- 生成后要求试讲，并根据实际用时调整。

## 五、版本失效规则

文字版锁定后发生任何改动，无论是事实、结构还是措辞：

1. 将文字版状态改为“待二次确认”，版本进入下一轮草稿；
2. 将现有交接包状态立即改为“已失效”；
3. 在交接包记录失效原因、失效日期和最后有效的文字版版本；
4. 禁止下游继续使用旧交接包；
5. 用户重新确认文字版并锁定新主版本后，重新生成完整交接包。

不要只局部修补旧交接包，因为逐页策划、讲者备注和事实映射可能受到连锁影响。
